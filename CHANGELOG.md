# Changelog

Notable changes per release. Dates are in UTC.

## [Unreleased]

### Added

- Desktop apps now run as real background residents (ROADMAP P1.1/P1.2): a tray icon with menu (open window / pause-resume listening / quit, plus pending-sync count), closing the window hides it to the tray while listening is on, and macOS no longer quits when the last window closes (Dock click re-opens the window).
- Offline upload queue (ROADMAP P1.4): clipboard text that fails to upload after retries is persisted locally (up to 500 entries) and re-uploaded automatically when the connection recovers or a new key is saved — no more silently lost clips on flaky networks. 401 keeps the queue until a valid key is set; 413 drops the offending entry with a visible notice.
- Sync status visibility (ROADMAP P1.5): pending-sync count and last successful sync time in the tray menu and in the history toolbar; queue-full situations raise a dismissible banner.
- `GET /api/v1/meta` (public) returns the server version and per-account limits (ROADMAP P3.3). The client stores them after a successful connection check and uses the reported byte cap for its local oversize pre-check.
- In-memory sliding-window rate limiting (ROADMAP P3.1, on by default): register/login per source IP (10/min) and upload per account (120/min), configurable via `rate_limit.*` / `DRIFTCLIP_RATE_LIMIT_*`; responses use 429 with `Retry-After`.
- Web Keys page connection guide (ROADMAP P2.3): step-by-step onboarding with a client download link, the server address, and a QR code encoding `driftclip://connect?server=…&key=…`.
- Client config import (ROADMAP P2.4): "从剪贴板导入" parses the connection string on every platform; Android/iOS additionally offer QR scanning via camera.

### Fixed

- Android release APK could not access the network at all: the `INTERNET` permission was only declared in the debug/profile manifests, not the main manifest. It is now declared for all builds, and the launcher app name is `DriftClip` (was `driftclip_client`) with the brand launcher icon.
- Android 9+/iOS no longer block self-hosted plain-HTTP servers: cleartext traffic is permitted (`network_security_config` / ATS exception) so `http://LAN-IP:8080` works out of the box; HTTPS remains recommended. iOS display name is now `DriftClip`.
- Oversized clipboard text (over the per-record limit) is no longer silently retried and dropped: the client pre-checks the byte limit locally and rejects immediately with a visible banner; a server `413` response stops retrying and shows the server's reason. (#ROADMAP P0.6)
- macOS "launch at login" is now actually implemented (ROADMAP P1.3): the `launch_at_startup` plugin ships no macOS native side, so the app provides its own SMAppService-based MethodChannel (`driftclip/desktop`, macOS 13+). The toggle is shown again on macOS. Needs on-device verification of the Login Items entry.

### Changed

- API keys can now be re-revealed and copied at any time on the web **Keys** page. The server stores an AES-256-GCM encrypted copy of each key (encryption key derived from `key_pepper`); the peppered-hash used for authentication is unchanged. Keys generated by older versions have no encrypted copy — revealing them returns 409 until the key is reset.
- Android release builds are now signed with a real keystore when provided (CI secrets `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`, or local `client/android/key.properties`); without one they still fall back to debug signing for local verification. See DEVELOPMENT.md "Android 签名".
- The client now reports its version from the pubspec-defined package info instead of a hard-coded constant that had drifted out of sync.
- Default per-account history retention raised from 100 to 1000 records (ROADMAP P3.2) so the "never lose a link" promise survives normal daily use; lower it via `history.max_history_records` if desired.

## [0.1.0] — 2026-09-23

First public release.

### Added

- Go + SQLite server: account registration/login (Argon2id), per-account API keys (shown once, peppered hash at rest), clipboard history API with per-account isolation, retention caps (100 records / 100 KiB per record by default), trusted-proxy + `require_https` enforcement
- React web client: history list with platform/text/time filters, detail view, copy, single/batch delete, clear-all with 5s confirmation, key management, settings
- Flutter native clients for Windows / macOS / Linux / Android / iOS: clipboard monitoring, manual input, history browsing with filters, key-based auth, configurable server address
- Docker Compose deployment and multi-stage Dockerfile
- CI (server/web/client) and release pipeline: multi-platform client builds, server bundles, GHCR image
